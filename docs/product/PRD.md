## 1. 产品定位与决策来源

**dshjob 是面向 AI 新手的免费找工作自动化项目官网。** 网站用亲和的语言、实际效果和分步教程，帮助求职者了解项目，通过 Gitee / GitHub 获取软件或项目，再在自己的电脑上使用，由 Agent（智能体）驱动求职流程。遇到问题可联系作者 simon。

网站是静态 HTML / CSS / JavaScript 页面。浏览、演示、教程、仓库跳转与联系入口在网站内完成；安装、招聘平台登录、岗位采集、拟稿及求职操作在用户自己的工具环境中完成。

| 编号 | 用户已明确的需求 | PRD 中的落点 |
|---|---|---|
| U-01 | 面向不熟悉 AI 的人，门槛低、亲和 | 第 2、5、6 节 |
| U-02 | 由 Agent 直接驱动，追求开箱即用 | 第 3、6、7 节 |
| U-03 | 静态网页，非 SaaS；提供 Gitee、GitHub 入口 | 第 4、5、7 节 |
| U-04 | Agent、Skill、MCP 形态都可以 | 第 5、7、10 节 |
| U-05 | 项目免费公开 | 第 7 节；不自行扩展为特定开源许可证或无限免费模型服务 |
| U-06 | 联系人 simon，微信 simonsxxs，使用提供的二维码 | 第 8 节 |
| U-07 | 要有粒子光束动效，参考 simonsxxs/dshopc | 第 9 节 |
| U-08 | 探讨 → PRD → Spec → 原型 → Kimi 实现 | 第 14 节 |
| U-09 | GitHub 为 simonsxxs/dshjob，Gitee 为 simonsxx/dshjob；部署路线参考 dshopc.com | 第 10.2、14.1 节 |
| U-10 | 不用黑色背景，已认可浅雾蓝原型 v2 | 第 9 节；Spec 细化尺寸与交互 |
| U-11 | 使用方式增加软件下载 | 第 5、6、7、10、12 节；只新增官网入口与教程，不开发安装包 |

本版沿用已认可的浅雾蓝背景、白色卡片、深蓝文字与蓝青色光束；保留“dshjob · AI 找工作助手”、首页加独立教程页的提案。新增软件下载后，获取区从三种扩展为四种使用方式，软件下载置首。性能、具体交互和安装包条件随 PRD / Spec 一并审阅；软件下载置首不表示已有可运行安装包。

## 2. 目标用户与问题

**主要用户：** 会使用电脑浏览网页、正在找工作，但不熟悉 AI 工具安装和配置的个人求职者。

**次要用户：** 已使用某种 Agent，希望给它增加找工作能力的人。其 Skill（技能包）或 MCP（工具连接协议）接入说明应容易找到，但不要求所有新手先理解这些术语。

| 用户的问题 | 网站提供的帮助 |
|---|---|
| “它到底能帮我做什么？” | 以搜岗位、筛选、拟稿、整理进度等场景解释，并说明平台差异 |
| “真的能用吗？结果是什么样？” | 展示经核实的截图或演示，标清演示数据、版本和能力边界 |
| “下载后不知道怎么办。” | 给出下载、打开项目、对 Agent 说第一句话、查看结果的连续指引 |
| “这些版本看不懂。” | 每种形态先说明适合谁、需要什么、下一步做什么，再展示技术名称 |
| “会不会替我乱发消息？” | 明示由本人完成登录、真实发送需本人授权、异常时停下 |
| “卡住了找谁？” | 教程和页面底部提供 simon 的微信与二维码 |

手机访问者能够阅读、了解项目、复制仓库链接或微信号；官网适配手机不代表求职工具已支持手机运行。工具系统兼容范围须单独验收。

## 3. 产品目标与成功标准

| 编号 | 目标 | 验证方式与拟定达标线 |
|---|---|---|
| SM-01 | 新手看得懂 | 邀请 5 名目标用户看首页 30 秒，至少 4 人能说清用途、免费获取方式、实际在哪运行 |
| SM-02 | 找得到入口 | 同一组用户至少 4 人在 60 秒内找到仓库与对应教程；仅能找到作者主页不算成功 |
| SM-03 | 教程可照做 | 对首版推荐路径，至少 4 人在不需要作者额外口头解释的情况下找到正确下载物并完成教程要求的首次打开；准备条件、耗时与失败点如实记录 |
| SM-04 | 首次求职流程可验证 | 发布前在声明支持的系统及 Agent 上，用干跑流程验证“需求输入 → 岗位结果 → 看板”；没有岗位时展示真实空态。自测通过不替代首次上手验收 |
| SM-05 | 动效不影响使用 | 第 9、11、12 节检查通过；用户能够阅读、滚动、点击和主动暂停动效 |
| SM-06 | 内容可信 | 所有可点击仓库链接、能力描述和演示素材均有来源；缺资料时不编造 |

上述目标是待执行的验收要求，本轮没有开展用户测试或求职实操。“开箱即用”是工具上手体验目标：已具备前置条件时可按指引开始；缺条件时，Agent 或教程能明确引导。未经安装验收，不宣传“零准备”“一分钟必成功”。

首版不接入访客追踪、转化统计服务或收集个人资料；以上指标通过邀请测试、人工记录与浏览器检查验证。

## 4. 首版范围

### 4.1 必须交付

- 首页 `index.html`：定位、粒子光束首屏、能力介绍、结果示例、使用概览、工具获取、FAQ、联系作者。
- 教程页 `guide.html`：从获取项目到第一次运行的分步说明，包含不同工具形态的接入差异与错误处理。
- 软件下载、Agent、Skill、MCP 四种使用入口；Gitee / GitHub 项目与发布物链接、可核实的获取说明、教程内定位链接。
- 桌面及移动端布局；基础导航、按钮反馈、演示切换、复制反馈、动效开关。
- 作者微信原图、文字账号和无需扫码的联系方式。
- 静态降级、基础可访问性、页面标题与描述、正确的内部链接。

### 4.2 本次不包含

- 网站账号、注册登录、付费、订阅、在线客服系统、管理后台、数据库。
- 在官网运行 Agent、连接本地服务、登录招聘平台、提交简历或启动投递。
- 修改兄弟项目的 Agent、Skill、MCP、安装器、招聘规则或现有账号配置。
- 多账号求职、岗位聚合搜索服务、云端托管任务、手机运行工具。
- 新建商城、论坛、文章系统、多语言站、复杂版本管理或访客行为分析。
- 当前 Spec 阶段只维护方案文档，不生成页面代码、安装依赖、启动开发服务、制作或发布软件安装包。

## 5. 页面结构与主要入口

### 5.1 首页

桌面导航：**能做什么 / 看看效果 / 获取工具 / 使用教程 / 联系 simon**。前三项和联系作者定位首页区域，使用教程进入独立页面。移动端用明确标注的菜单按钮，点击条目后关闭菜单并到达目标。

| 区域 / 锚点 | 用户需要得到的答案 | 内容与行为 |
|---|---|---|
| 首屏 | 是什么、对我有什么帮助 | 简短定位、免费公开标记、两个主行动、粒子光束与求职结果示意 |
| 能做什么 `#features` | 哪些重复工作能交给 AI | 岗位搜集、条件筛选、沟通拟稿、进度整理；平台支持差异另列 |
| 看看效果 `#demo` | 跑完后是什么样 | “说出需求 / 查看岗位 / 查看进度”三张静态示例，用户主动切换，始终标注演示性质 |
| 使用概览 `#start` | 从哪里开始 | 获取项目 → 按引导准备 → 告诉 Agent 求职需求 → 查看结果；每步可进入对应教程 |
| 获取工具 `#downloads` | 选什么、从哪里获取 | 按软件下载、Agent、Skill、MCP 顺序展示四类卡片，每类说明适用对象、前置条件、状态、仓库与教程；软件下载附已确认的系统与安装包信息 |
| 常见问题 `#faq` | 免费范围、操作边界、兼容性 | 可展开的问题列表，问题和回答存在于页面正文中 |
| 联系 simon `#contact` | 卡住时找谁 | simon、微信 simonsxxs、复制按钮、原始二维码 |
| 页脚 | 谁做的、如何返回 | 作者署名、首页及教程链接、仓库链接；域名与版权信息按正式发布资料核对 |

**首屏文案草案：**

> dshjob · AI 找工作助手
>
> **让 AI 帮你找工作，从这里开始。**
>
> 搜集岗位、筛选机会、整理求职进度，让求职中的重复工作轻松一点。
>
> 项目免费公开，跟着教程交给 Agent 使用。

主按钮“免费获取工具”跳到 `#downloads`；次按钮“查看使用教程”打开 `guide.html`。不将按钮命名为“立即运行”，以免用户误认为官网已接入自己的招聘账号。

首屏右侧建议展示简洁的求职需求与结果卡片，不设置可输入真实简历、手机号或求职需求的假聊天框。卡片示例文案可以是“我想找上海的运营岗位，先帮我筛选，不发送消息”；卡片不是可执行指令入口。

### 5.2 教程页

教程页顶部提供“返回首页”“获取工具”“联系 simon”，页面内提供章节目录。提供 `#software`、`#agent`、`#skill`、`#mcp` 四种方式的独立章节，以经核实的新手路径优先展开；首版不建设独立文档站。软件下载教程按“确认系统和版本 → 到发布页获取安装包 → 按实际安装向导打开软件 → 完成必要准备 → 输入首次干跑需求 → 查看结果”编排；安装条件未核实时只显示准备状态和已知信息，不编造安装步骤。

| 教程步骤 | 必须说明的内容 | 完成标志 |
|---|---|---|
| G-01 使用前准备 | 支持的系统、Agent 及版本、浏览器扩展、必要运行环境；区分已验证与待确认 | 用户能判断自己的环境是否适用 |
| G-02 获取软件或项目 | 软件说明系统、芯片架构和实际安装包；项目说明仓库下载位置、解压和目录识别；截图与真实版本一致 | 用户拿到对应方式的正确文件，而不是只打开作者主页 |
| G-03 交给 Agent | 具体在哪个软件打开哪个文件夹，或如何安装 Skill / 配置 MCP；分别说明 | Agent 能识别项目及其使用说明 |
| G-04 检查与登录 | Agent 检查环境，缺条件时提示下一步；本人处理登录、扫码和验证码 | 相关环境就绪；未就绪则停止并显示缺项 |
| G-05 说出求职需求 | 城市、岗位、筛选条件；提供可复制的干跑提示语 | Agent 回报理解到的需求与本次动作范围 |
| G-06 查看结果 | 去哪里看岗位、拟稿和进度，说明空结果与失败状态 | 用户看到真实结果或明确空态，知道下一步 |
| G-07 需要帮助 | 常见故障处理、收集非敏感错误信息、联系 simon | 能复制微信号或查看二维码，不上传隐私资料到官网 |

教程提示语草案（须对最终推荐包验证后才发布）：

> 请先阅读这个项目的使用说明，检查运行条件，再引导我补充求职需求。先执行筛选、拟稿和记录，不发送消息、不投递简历；需要登录或授权时停下来告诉我。完成后告诉我在哪里查看结果。

## 6. 用户流程与职责边界

**UJ-01 首次访问：** 浏览首页 → 看懂用途和示例 → 打开获取区域 → 查看适用条件 → 选择 Gitee 或 GitHub → 到仓库获取项目 → 返回或继续查看对应教程。

**UJ-02 已有 Agent：** 从工具卡进入对应章节 → 按已验证方式添加项目 / Skill / MCP → 在该 Agent 内检查环境并输入需求 → 按工具自身流程查看结果。网站不检测用户电脑上是否已安装软件。

**UJ-03 遇到困难：** 教程步骤或 FAQ → 找到相符故障说明 → 查看下一步 → 仍无法解决时复制 simon 微信号或扫码添加。扫码后的处理由用户在微信中完成，网站不检测是否成功加好友。

**UJ-04 手机浏览：** 阅读与查看演示 → 复制仓库链接留待电脑使用，或联系 simon。用户点击原生外链后由设备浏览器处理；不宣传手机可直接完成整个求职流程。

**UJ-05 下载软件：** 获取区选择“软件下载” → 阅读支持系统、版本及前置条件 → 选择已核实的 Gitee / GitHub 安装包发布入口 → 用户自行下载和安装 → 按 `guide.html#software` 首次打开并使用。系统或安装包未确认时，卡片显示“安装包准备中”，提供仓库与求助入口；不自动开始下载、安装或调用本地软件。

| 承担者 | 负责的事情 |
|---|---|
| 静态网页和普通 JavaScript | 展示资料、导航、演示切换、复制、动效与反馈 |
| 用户使用的 Agent | 在自己的运行环境中理解求职需求、调用已支持的工具、回报结果 |
| 求职工具和浏览器扩展 | 根据已验证的能力执行采集、拟稿、落账；具体边界来自对应项目 |
| 用户本人 | 安装或权限确认、招聘账号登录、真实发送的授权、敏感沟通和人工处理 |
| simon | 提供人工帮助入口；网站不承诺服务时间、响应时限或求职结果 |

## 7. 功能规则与状态

| 编号 | 要求 | 验收要点 |
|---|---|---|
| FR-01 | 导航、锚点与主按钮到达明确目标 | 粘性导航不遮挡目标标题；前进后退正常；不以滚动动画阻塞点击 |
| FR-02 | 下载区按软件下载、Agent、Skill、MCP 展示，允许共用仓库 | 每项说明用途、准备条件、资料状态；软件下载与项目 / 插件 / 接入包区分，不能将源码 ZIP 称为软件安装包 |
| FR-03 | 每种使用方式保留经过核对的 Gitee 与 GitHub 项目仓库入口，发布物来源分别核实 | 新窗口打开时给出外链提示；作者主页不是下载目标。缺失安装包的来源显示准备状态，不以仓库源码替代 |
| FR-04 | 区分仓库入口与可用工具包 | 地址未知时显示不可点击的待补状态；已知仓库只有官网源码时可“查看仓库”，但不能标为已经可以获取求职工具。主路径的工具包 / 目录及双来源在发布前核实；不用 `#`、示例域名或 dshopc 参考仓库冒充 |
| FR-05 | 教程有适用条件、连续步骤和错误出口 | 不要求新手自己猜工作目录、软件名称和操作位置；复制提示语只复制，不自动发送给 Agent |
| FR-06 | 复制行为有成功与失败反馈 | 成功才提示“已复制”；权限被拒、非安全上下文或浏览器不支持时显示可选中文本及手动复制方法 |
| FR-07 | FAQ 回答核心疑问 | 覆盖免费范围、运行位置、平台差异、必要准备、真实发送、手机使用、数据与求助 |
| FR-08 | 项目获取免费，无站内购买流程 | 项目免费与用户另行使用的模型/Agent 服务费用分开说明；不擅自声明第三方全部免费，也不添加付费门槛 |
| FR-09 | 演示与真实状态区分 | 示例数字、虚构岗位及预录过程明确标注；不显示假在线人数、虚构评价或实时求职进度 |
| FR-10 | 页面在基础脚本失败时仍可阅读和获取 | 标题、正文、链接、教程与微信号由 HTML 提供；演示默认内容可见，FAQ 保留可访问答案 |
| FR-11 | 静态官网不接收求职个人数据 | 不上传简历、采集招聘账号或调用本地 Agent；工具自身的数据流不等同于官网，需要按实际工具说明 |
| FR-12 | 公开与开源用词准确 | 使用“免费公开”；只有核实仓库许可证后才写具体开源授权，不从“免费”推导可商用或任意再分发 |
| FR-13 | 软件获取有明确平台、版本和可用性 | 仅已核实的系统 / 架构组合提供下载链接；每项有版本、包名、更新日期、大小及对应教程。尚未提供的版本不显示虚构下载按钮；不自动探测本机安装、自动下载或报告下载成功 |

### 9.3 动效矩阵

| 编号 | 场景 | 预期表现与限制 |
|---|---|---|
| MOT-01 | 首页首屏 | 至少一条可辨识的弧形光束及沿其运动的细粒子；多层亮度构成景深，缓慢、连续，无强闪烁或突发爆炸 |
| MOT-02 | 桌面鼠标移动 | 光束或局部微粒轻微响应，建议位移上限 8px；不推动文字、按钮或整个页面，离开后平滑回稳 |
| MOT-03 | 向正文滚动 | 光束形态或亮度柔和过渡，阅读区明显减弱；不锁滚动、不强制逐屏、不要求等动画播完 |
| MOT-04 | 卡片与按钮 | 使用 160–240ms 的轻反馈；区块出现可使用 240–400ms 淡入和不超过 16px 位移；正文最终位置不跳动 |
| MOT-05 | 教程和二维码区 | 教程正文无持续背景运动；二维码周围使用稳定底色，动效不穿过图片或联系方式 |
| MOT-06 | 手机与触摸 | 不依赖悬停；降低密度、分辨率和模糊开销，必要时显示静态光束；点击和滚动正常 |
| MOT-07 | 减少动态效果 | 系统 `prefers-reduced-motion` 开启时，关闭连续流动、鼠标扰动、位移入场和平滑滚动，立即展示完整内容与静态光晕 |
| MOT-08 | 主动控制 | 有可发现且支持键盘的“暂停动效 / 开启动效”按钮，状态真实可读；本页有效即可。系统减少动态效果优先，不因点击强制恢复强动效 |
| MOT-09 | 隐藏与失败 | 页面隐藏时停止动画计算；恢复可见时尊重当前暂停状态。图形能力不可用、初始化失败或上下文丢失时静态回退，正文与链接不受影响 |
| MOT-10 | 绘制层级 | 装饰层不接收点击、不进入键盘顺序，不遮挡焦点、菜单、正文或按钮；任意状态最多保留一个背景动画循环 |

持续动效优先让首屏建立记忆点；运动强度与性能不满足目标时，可降低粒子数量、亮度与模糊质量，保留光束主题。完全静态状态也必须是完整设计，而不是黑屏或报错。

参考代码采用 React / Rspress 与 WebGL2；本站现行约束仍是无构建步骤的静态 HTML / CSS / JavaScript。配套 Spec 选择原生 Canvas 2D 粒子与静态 SVG 光束，说明回退与预算；不直接搬入参考项目的框架或依赖。渲染细节以 Spec 为准。

### 14.1 托管部署路线

按用户要求参考 dshopc 的实际发布配置，采用：

**GitHub 代码版本 → GitHub Actions 人工触发并校验 → Cloudflare Pages Direct Upload（上传静态文件）→ dshjob.com。Gitee 保留对应版本的公开获取入口。**

| 项目 | dshjob 的目标要求 | 当前状态 |
|---|---|---|
| 发布代码源 | `https://github.com/simonsxxs/dshjob`，生产分支拟定 `main` | 该仓库与 main 已存在；尚未创建本项目发布工作流 |
| Gitee 对应仓库 | `https://gitee.com/simonsxx/dshjob`，发布版本可对应 | 本轮 HEAD 一致；后续双端同步方式在 Spec 固化，不将同步当作部署 |
| 静态托管 | Cloudflare Pages，独立项目名拟定 `dshjob` | 未核验项目是否存在，不复用 dshopc 生产项目 |
| 正式域名 | `https://dshjob.com`，HTTPS 和教程路由正常 | 目标域名已在项目说明中约定；本轮未配置或验证绑定 |
| 发布方式 | GitHub Actions 手动触发；校验获批的完整 commit SHA 属于远程生产分支，再上传 | 参考已有 dshopc 工作流；不因普通 push 自动发布 |
| 上传产物 | 仅网页 HTML、CSS、JS、公开素材及所需静态站点文件 | 用文件白名单打包；具体目录由 Spec 定义，不直接上传仓库根或照抄 `doc_build` |
| 凭据 | GitHub 安全存储中的 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` | 本轮只记录名称，未读取、创建或修改值 |
| 发布后证据 | SHA、Actions run、Pages deployment ID、不可变 URL、正式域名与页面验收 | 实际发布后记录；失败和回滚均须对应授权 |

参考 dshopc 的 `.github/workflows/release-pages.yml` 与 `docs/RELEASE.md`（同第 9.1 节参考提交）：其路线为人工触发、校验准确提交、Wrangler 上传 Pages、检查正式域名。dshopc 的 Rspress 构建、`pnpm verify` 与 `doc_build` 属于它自己的工程；本站只保留静态文件校验和必要上传打包，不因此引入它的前端构建栈。CI 中的发布工具不成为访客或本地网页运行依赖。
