## Context

本设计对应 [proposal.md](proposal.md) 与 [PRD v1.1.0 draft](../../../docs/product/PRD.md)，当前为待审阅规格。代码仍是占位页。用户已认可[浅雾蓝 v2](../../../prototype/visual/homepage-v2-light.png)，并增加软件下载；图片用于视觉基线，文字、资源状态及四入口规则以本次文档为准。

## Goals / Non-Goals

**Goals:** 新手知道能做什么、选哪种方式、去哪里获取、第一次如何操作及卡住时如何联系；在浅色界面中保留可辨识的粒子光束，支持手机与静态回退。

**Non-Goals:** 开发软件或安装器、在线运行 Agent、招聘平台数据读写、登录支付后台、引入框架 / 构建系统、自动发布、修改兄弟项目。

页面内链接使用 `index.html`、`guide.html#software` 等相对文件路径，方便双击打开。Cloudflare 会将 `.html` 转到无扩展名路径，所以正式 canonical / sitemap 使用 `/`、`/guide`，发布时验证跳转后锚点仍保留。[Cloudflare 路由说明](https://developers.cloudflare.com/pages/configuration/serving-pages/)

### 2. 页面结构和文案

#### 首页

保持 v2 的层次和留白，不能将图片作为整页背景覆盖真实 HTML。

| 顺序 | 区域 | 具体内容与去向 |
|---|---|---|
| 0 | 导航 | dshjob 标识；能做什么、看看效果、获取工具、使用教程、联系 simon；右侧动效控制 |
| 1 | 首屏 | 免费公开小标、标题“让 AI 帮你找工作，从这里开始。”、两句用途解释；主按钮到 `#downloads`，次按钮到 `guide.html` |
| 2 | 能做什么 | 搜集岗位、筛选机会、沟通拟稿、整理进度四卡；平台差异说明链接到教程 |
| 3 | 看看效果 | 三视图：说出需求 / 查看岗位 / 查看进度；同一组虚构示例，始终显示“演示数据” |
| 4 | 四步开始 | 选择方式 → 跟着教程准备 → 告诉 AI 求职需求 → 查看结果；分别定位教程或下载区 |
| 5 | 获取工具 | 四卡，见第 4 节；标题“选一种适合你的方式，开始使用” |
| 6 | FAQ | 原生 details / summary，至少覆盖费用、方式差异、电脑条件、平台能力、真实发送、手机、数据、求助 |
| 7 | 联系 | “遇到问题？找 simon 帮忙。”、微信 simonsxxs、复制、大图入口和真实二维码 |
| 8 | 页脚 | 作者 simon、仓库、教程及必要版权信息；不新增虚构备案号或资质 |

首屏右侧用只读需求 / 结果卡，不放真实输入框。示例：“我想找上海的运营岗位，先帮我筛选，不发送消息”。短说明：“工具在你的电脑上使用，按教程准备好环境后，由 AI 帮你完成重复工作。”

统一概览不声称所有方式都需要解压，也不声称所有方式都只需安装软件；先选方式后进入各自步骤。v2 中三张工具卡、重复编号、二维码占位和小字不能直接照搬。

#### 教程

顶部为“跟着做，开始第一次使用”，先显示四种方式的页内导航，之后是四个常驻 HTML 章节，无须选择才能加载。

- `#software`：适合想安装后使用的人；系统 / 架构和已验证版本；真实安装包入口；实际安装 / 打开说明；准备条件；首次干跑和结果位置。信息未齐时保留该章节，清楚展示准备状态。
- `#agent`：适合已有 AI 智能体的人；指出已验证宿主、如何打开真实项目、Agent 检查与提示语。
- `#skill`：适合给已有 AI 工具添加技能的人；宿主条件、技能目录和真实导入方式，不与软件安装步骤混用。
- `#mcp`：适合已有支持 MCP 的客户端的人；客户端条件、已核实配置与连接判断；不要让新手误以为本网页就是 MCP 服务。
- `#help`：下载失败、找不到入口、环境缺失、首次运行失败、无结果和人工接管；每项有下一步及联系锚点。

软件准备状态文案：“安装包正在准备中。系统版本和下载入口确认后，会在这里补齐。你也可以先查看其他使用方式，或联系 simon。”其他方式的未知资料采用相同诚实规则。

一条首次提示语可复用 PRD 第 5.2 节，正文可选中，复制只写剪贴板。已知的登录、账号授权和异常停下规则用普通话描述，不把工具源码内部闸门名展示成新手操作步骤。

#### 色值

| 用途 | 色值 / 规则 |
|---|---|
| 全页底 | `#F2F7FC` |
| 首屏 | `#E9F3FF` → `#F5FAFF` 柔和渐变 |
| 内容卡 | `#FFFFFF`，细边 `#C8DAEB`，轻阴影 |
| 标题 / 正文 | `#16324F` |
| 次要说明 | `#516579`，不能将重要条件变成低对比浅灰 |
| 主按钮 | `#2563EB` 配白字；悬停 `#1D4ED8` |
| 粒子 / 光束 | `#3689F5`、`#58BDD9`，只作装饰，不用于浅底小号说明文字 |
| 联系区域 | `#E7F1FF`，二维码下面另用白底 |

2026-09-15 以 sRGB 相对亮度计算：正文 / 页面底约 12.15:1，次要字 / 页面底约 5.59:1，白字 / 主按钮约 5.17:1。v2 提示词的 `#3478F6` 白字约 4.07:1，因此将按钮轻微加深；保留整体视觉方向。透明、叠加光晕及所有 hover / focus 态还需按最终渲染检查。

#### 排版和网格

- 字体：系统中文字体栈，`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`；不阻塞加载远程字体。
- 内容最大宽 1184px；页面两侧：手机 20px，平板 32px，桌面至少 40px。导航桌面高约 72px、手机约 64px，锚点留导航高度 +16px。
- H1：桌面约 56px / 1.15，平板 44px，手机 36px；区块标题约 32px / 28px；正文 16–18px、行距 1.65。
- 区块上下间距桌面 80–96px、手机 48–56px；卡片内边距 24px，手机 20px；间隙 20–24px；卡片圆角 20px、按钮 12px。
- ≥1100px：首屏左右两列约 55:45，功能卡和四入口均四列；联系区域两列。
- 640–1099px：卡片两列；首屏宽度不足时改上下排列；教程目录可收为上方普通目录。
- <640px：首屏文案在上、示意在下，主次按钮均可整行；卡片单列；联系上下排列，二维码显示宽约 200–240px，保留原比例。
- 桌面教程主体为约 220px 目录 + 最大 760px 正文；手机目录在正文前，按内容高度排版。段落不放进固定高度滚动小窗。
- 岗位示例桌面可为表格，手机改成逐岗位块；避免靠横向滚动才能读到必要字段。源码只维护一份语义数据或文本，若双展示必须避免读屏重复朗读。

### 4. 四入口及下载状态

| 顺序 / 教程锚点 | 面向用户的标题 | 适合谁 | 必需说明 |
|---|---|---|---|
| 1 / software | 软件下载 | 想先装好软件，再按引导使用 | 系统、架构、版本、安装条件、发布物状态 |
| 2 / agent | Agent 智能体 | 已有 AI 智能体，想让它带着做 | 已验证宿主、项目获取及打开位置 |
| 3 / skill | Skill 技能包 | 想给现有 AI 工具增加求职技能 | 宿主、技能导入方法及作用范围 |
| 4 / mcp | MCP 工具接入 | 已使用支持 MCP 的客户端 | 客户端条件、工具接入及实际平台范围 |

四卡始终并列可读，不做默认隐藏三种方式的复杂选择向导。软件卡置首是设计次序，不是成熟度声明；“新手推荐”只有完成该路径安装 / 上手验收后可添加。

软件在多系统时使用原生 `details` 展示各条目，每个系统 / 架构占独立行；默认无自动识别和强制预选。已确认版本较少时直接展示，避免添加无实际选项的空下拉框。

#### 资料字段

资料作为 HTML 文本与 `data-*` 静态属性维护，**不是要开发动态配置系统**。所有未知 URL 使用空值并不渲染链接。

| 字段 | 含义 |
|---|---|
| `mode` | software / agent / skill / mcp |
| `status` | pending（准备中）/ repository-only（可看仓库）/ ready（可获取）/ unavailable（当前不可用） |
| `title`、`audience`、`prerequisites` | 面向用户的名称、适用对象、必要条件 |
| `guideAnchor` | 对应四个教程章节之一 |
| `githubRepository`、`giteeRepository` | 用户已提供的两个项目仓库 |
| `artifacts[]` | 软件仅列已确认的系统 / 架构组合；未知时为空 |
| 每个软件 artifact | os、architecture、version、fileName、size、updatedAt、notes、sourceStatus、真实来源 URL、verifiedAt |

每个下载源独立记录状态。`ready` 至少需要一个真正可获取的安装包来源及完整已核实资料；另外一个缺失不能渲染成下载按钮。对可用发布页用“前往 GitHub 下载”/“前往 Gitee 下载”，已知直接附件用“下载 [系统 / 架构] 安装包”；明确外部去向。源码用“查看 GitHub 仓库”/“查看 Gitee 仓库”，不共用模糊的“下载”标签。

软件条目从 ready 变为 unavailable 时保留版本和说明，取消该条目的下载链接；本站不后台轮询仓库状态，维护者按核验更新。跨来源的文件和版本必须一致，否则标明版本差异，不偷偷下载另一个系统或旧版本。

### 5. 普通交互与降级

- 移动菜单使用非模态展开导航；按钮仅在 JS 初始化完成后出现，控制 `hidden` 和 `aria-expanded`。无 JS 时导航保持普通可见链接；避免初始化失败把全部导航藏住。
- 演示三个面板初始均有真实 HTML；JS 完成后才增强成 `tablist`，支持方向键、Home / End、Enter / Space，`aria-selected` 与唯一可聚焦 tab 同步。手机高度按内容变化，不固定裁切。
- FAQ 使用原生 `details/summary`；允许同时展开多个问题，无 JS 也工作。
- 复制控件仅在增强后出现；`navigator.clipboard.writeText` 成功才经 `aria-live="polite"` 显示约 2 秒“已复制”。失败保留完整可选文本与“请长按或选中文字手动复制”，不强制请求额外权限。
- 手机软件卡提示“请在支持的电脑上使用”，提供复制仓库 / 已核实包链接；不屏蔽用户主动打开外链，不自动下载。
- 二维码大图为原生图片链接，不做遮挡式弹窗；图片设宽高、保持比例。原图失败时显示文字联系方法。
- 动效图层 `aria-hidden`、`pointer-events: none`；不承载正文、按钮或被复制文字。

### 6. 光束实现与状态机

首版采用 **静态 SVG 弧形光束 + 原生 Canvas 2D 细粒子**，不引入 React、Three.js、WebGL 或第三方动画库。静态底图先出现，后续粒子沿 2–3 条弧线路径缓慢流动；保留 v2 轻盈的蓝青线条，避免白光在浅底上消失。

采用这一方案是为了满足无构建、少资源、静态可回退的约束。用预绘小粒子贴片及少量轨迹，避免每粒每帧大量 blur；绘制通过 `requestAnimationFrame` 调度。这与 [MDN Canvas 优化建议](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)一致。具体粒子数量是本站预算，需画面和性能联合验收，不能等同参考站 WebGL 效果已复现。

| 档位 | 条件与预算 |
|---|---|
| desktop | ≥1100px 且精细指针；最多 360 粒子，DPR 上限 1.5；目标 50–60fps；鼠标位移最多 8px |
| compact | 中等视口；最多 180 粒子，DPR 上限 1.25；关闭鼠标扰动；目标至少 30fps |
| mobile | <640px 或粗指针；最多 100 粒子，DPR 上限 1；目标至少 30fps；无鼠标响应 |
| static | 系统减少动态、用户暂停、能力失败或低档仍慢；0 动画帧，静态光束可见 |

控制器保留 `userPaused`、`reducedMotion`、`pageVisible`、`heroVisible`、`quality`、`failed` 独立状态，不能用单个按钮文字推断状态。

```text
允许绘制 = !userPaused && !reducedMotion && pageVisible && heroVisible && !failed
初始静态底图 → 条件允许时运行
用户暂停 / 系统减少动态 / 页面隐藏 / 首屏离屏 → 取消当前帧
重新可见 → 重新评估全部条件，只恢复符合条件的状态
图形失败 → failed 锁定，本页保持静态，不反复重启
```

- 用 IntersectionObserver 管理首屏可见，scroll 只记录进度、绘制时消费；首屏离开前将亮度从 1 缓降到约 0.25，完全离开后停帧。正文、教程、联系区域不铺全屏漂浮粒子。
- 页面隐藏取消 rAF；恢复前重置时间基线，避免粒子大跳。任何时刻最多一个已排队 rAF，resize 只更新尺寸和当前状态，不重复注册循环。
- 内存中的用户暂停偏好本页有效即可，不设置 Cookie 或追踪。系统减少动态为最高优先级；此时开关显示“已按系统设置减少动效”且不能强制开启。
- 正常状态按钮为“暂停动效”，用户暂停后为“开启动效”；故障 / 性能静态时用“静态展示”状态说明。不能把离屏暂停写成用户主动暂停。
- 图形初始化 / 绘制异常、上下文丢失时取消帧，保留静态 SVG；本次页面不自动恢复失败渲染器。
- 每个连续可见的 2 秒窗口统计实际绘制帧率；桌面低于 45fps 或移动低于 28fps 连续 3 窗口，下降一档；降档后清空样本，最低档仍不达标则静态。排除隐藏 / 离屏时间，本页不自动升档，防止反复切换。
- hover / press 反馈 180–220ms；仅可选的区块入场 280–360ms、位移不超过 12px，不把正文默认设为永久透明。减少动态时取消位移与平滑滚动。

### 7. 发布文件与托管设计

采用用户指定路线：GitHub Actions 人工触发 → 固定提交校验 → 白名单暂存 → Cloudflare Pages Direct Upload。官方支持把准备好的静态文件目录通过 CI / Wrangler 上传；官方示例的自动 push 触发不适用本站人工发布要求。[Cloudflare CI 直接上传](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/)

**站点白名单：** `index.html`、`guide.html`、`404.html`、`robots.txt`、`sitemap.xml`，以及第 1 节列明的七个 `assets/` 文件。若新增教程截图，先在明确清单登记具体文件名再打包，不能改成整个 assets 目录递归放行。拒绝 symlink、目录穿越、缺失必需文件；打包到系统临时目录或新建专用暂存目录，不清理任意用户路径。

绝不上传 `docs/`、`openspec/`、`prototype/`、AGENTS、README、`.git/`、账号状态、求职项目或安装包。404 为浅色文字兜底，不计入内容栏目与 sitemap。若不提供顶层 404，Pages 可能按 SPA 返回首页，因此本站明确交付 `404.html`。[Cloudflare 404 规则](https://developers.cloudflare.com/pages/configuration/serving-pages/)

发布工作流草案要求：

1. 仅 `workflow_dispatch`；输入为完整 40 位 `commit_sha` 与人工确认值 `RELEASE dshjob.com`；无 push / PR / schedule 发布触发器。
2. 固定仓库 `simonsxxs/dshjob`、生产分支 `main`、目标 Pages 项目 `dshjob`，不接受用户输入任意目标覆盖。
3. 验证输入格式、commit 可取得且属于远程 main；checkout 后 HEAD 必须等于输入 SHA。发布依据始终是用户批准的精确 SHA，祖先关系检查不构成批准。
4. 静态检查通过，产物白名单确认后再上传；不需要 npm 构建网站。CI 的发布工具版本在实施时固定并记录，不把部署 CLI 变成访客依赖。
5. 仅读取 GitHub Secrets 的 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID`，不得输出内容；核对 Pages 项目归属后才执行。
6. 记录获批 SHA、Actions run、Pages deployment ID 和不可变 URL，再检查正式域名。工作流可写好供审阅，运行必须另有发布授权。

Gitee 同步属于另一个明确动作：需要推送授权后同步同一发布提交 / 标签，再读取两端确认一致；如尚未同步，报告状态，不将 GitHub 成功写成双仓库完成。安装包来源版本另核对，不由站点发布任务自动制作或上传。

## Risks / Trade-offs

- 软件资料缺失：可先验收真实准备状态的网页；不能把该状态当成软件可下载或整个主路径已可发布。至少一条完整获取 / 教程 / 上手路径闭环后，才可申请主站发布。
- 轻量 Canvas 与参考 WebGL 有表现差异：以 v2 浅色画面、沿束流动和可读性验收；如在预算内无法达到效果，回报差异，不直接引入框架。
- 新增四卡与未出图页面：桌面 v2 保留，四卡、教程和手机按本文实现后需要实际预览核对。
- 第三方链接变化：维护资料按版本刷新，软件和网站版本不要混淆；不部署爬虫或定时探测服务。
- 原始二维码仍待本人扫码：以原图加文字联系保证可用退路，扫码成功不能通过图像文件存在推断。
- PRD 与实施批准尚未完成：当前可交付规格和审阅材料，Kimi 不得将任务清单存在或 OpenSpec 通过当成自动开发指令。
